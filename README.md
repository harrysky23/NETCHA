# NETCHACAMELEON — Phase 1

화면 타이틀은 **CHROMIMIC**인 2D 탑다운 픽셀아트 게임의 로컬 싱글플레이 프로토타입입니다.
16×16 고정 실루엣 안을 8색으로 칠하고, 완성한 캐릭터로 작은 강의실을 탐험합니다.

React는 화면·에디터·캐릭터 상태를, Phaser 3는 맵·텍스처·키보드·이동·충돌을 담당합니다.
서버, WebSocket, 멀티플레이, 계정, DB, 역할, 타이머, 승패, 채팅, 사운드, 복잡한 애니메이션은 구현하지 않았습니다.

## 실행

필요 환경: npm, Node.js `^22.22.2 || ^24.15.0 || >=26.0.0`.
테스트의 jsdom을 포함한 전체 의존성이 요구하는 버전입니다.
실제 설치·빌드·테스트 환경은 macOS Apple Silicon, Node.js 26.5.1, npm 11.17.0입니다.

프로젝트 루트에서:

```sh
cd frontend
npm install
npm run dev
```

터미널에 출력된 Local 주소를 브라우저에서 엽니다. 기본 포트는 5173이며, 사용 중이면 다음 포트로 바뀝니다.
서버나 Python 설치는 필요하지 않습니다. npm 명령은 `frontend/` 안에서 실행합니다.

```sh
npm test          # Vitest 자동 테스트
npm run build    # 소스·테스트 TypeScript 검사 후 프로덕션 빌드
npm run preview  # 빌드한 dist를 로컬에서 제공
```

`package-lock.json`을 포함했으므로 재현 설치에는 `npm ci`도 사용할 수 있습니다.

## 플레이

1. **게임 시작**을 눌러 에디터로 이동합니다.
2. 팔레트의 색을 고르고 실루엣 안을 클릭하거나 왼쪽 버튼으로 드래그합니다.
3. **초기화**는 처음의 기본 무늬로 복원합니다. 팔레트 인덱스 0도 투명이 아닌 먹색입니다.
4. **완성 · 강의실 입장**을 누르면 현재 그림을 상위 상태에 저장하고 맵에 입장합니다.
5. **W/A/S/D**로 이동합니다. 입력되지 않으면 게임 화면을 클릭하거나 한/영 입력을 확인합니다.
6. **다시 칠하기**로 에디터에 돌아가 완성한 그림을 수정할 수 있습니다.

픽셀 버튼은 키보드 Tab으로 선택하고 Enter/Space로도 색칠할 수 있습니다.
캐릭터 데이터는 메모리에만 있습니다. 새로고침하면 초기화되며, 에디터에서 시작 화면으로 돌아가면 미완성 수정은 저장하지 않습니다.
게임에 재입장하면 지정된 생성 위치로 돌아갑니다.
화면은 좁은 창에 맞춰 줄어들지만, 플레이는 키보드·마우스가 있는 데스크톱을 대상으로 합니다.

## 핵심 코드 학습 가이드

### 1. 실루엣, 팔레트, 색 배열의 분리

```ts
type PixelCharacter = {
  width: 16
  height: 16
  colors: number[]
}
```

`colors[y * 16 + x]`가 한 픽셀의 팔레트 인덱스입니다. RGB 문자열 256개 대신 0~7 인덱스를 저장합니다.
실루엣은 `CHARACTER_MASK`에 따로 있으므로 색칠로 캐릭터 모양이나 투명도를 바꿀 수 없습니다.
미리보기와 Phaser 텍스처 모두 마스크가 `false`인 픽셀은 그리지 않습니다.

TypeScript의 `number[]`는 길이나 값의 범위를 보장하지 못합니다.
`isPixelCharacter(unknown)`가 너비·높이 16, 길이 256, 모든 값의 정수 여부와 0~7 범위를 런타임에 확인합니다.
희소 배열의 빈칸도 거부합니다. 텍스처 생성 직전에 검증하며, 향후 서버에서 받은 JSON에도 같은 검증 경계를 적용할 수 있습니다.

### 2. 드래그와 React 상태

`PixelEditor`는 로컬 초안 상태를 가지고, 완성할 때만 `onComplete(character)`로 부모 `App`에 전달합니다.
상태 변경 때 기존 배열을 수정하지 않고 새 배열을 만들어 React가 변경을 인식하도록 합니다.

포인터 좌표를 그리드의 화면 크기로 나눠 0~15의 픽셀 좌표로 변환합니다.
Pointer Capture로 그리드 바깥에서 버튼을 놓아도 입력 종료를 받습니다.
`pointerup`, `pointercancel`, 캡처 손실에서 획을 끝내고, 버튼을 누르지 않은 이동은 무시합니다.

빠르게 움직이면 포인터 이벤트 사이에 여러 칸이 생략될 수 있습니다.
`paintLine()`은 Bresenham 알고리즘으로 이전 칸과 현재 칸 사이의 정수 좌표를 채웁니다.
각 좌표마다 마스크를 검사하므로 가로지르는 경로의 실루엣 바깥은 바뀌지 않습니다.

### 3. React와 Phaser 사이의 경계

```text
PixelEditor 초안
    → onComplete(PixelCharacter)
    → App의 완성 데이터
    → GameCanvas의 입장 시점 스냅샷
    → new GameScene(character, callbacks)
    → CanvasTexture와 Arcade 플레이어
```

`GameCanvas`는 입장 시 한 번 복사한 캐릭터로 게임 인스턴스를 생성합니다.
부모가 일반적으로 리렌더되어도 게임을 재생성하지 않습니다. 게임 중 캐릭터 prop을 바꿔 실시간 교체하는 계약은 없으며,
수정할 때는 에디터로 나갔다가 새 데이터로 다시 입장합니다.

`useEffect` 정리 함수가 포커스 이벤트 리스너와 게임을 해제합니다.
초기 생성은 취소 가능한 `requestAnimationFrame`에 예약해서 개발 모드 StrictMode의 첫 setup/cleanup이 중복 게임을 남기지 않게 합니다.
게임 화면이 포커스를 잃으면 키 상태와 속도를 초기화합니다.
`App`은 `lazy()`로 게임 모듈을 입장 시점에 불러옵니다.

### 4. 텍스처와 Phaser 게임 루프

`createCharacterTexture()`가 투명한 16×16 Canvas에 마스크 내부만 1×1 사각형으로 채우고 `refresh()`로 텍스처에 반영합니다.
Canvas의 smoothing을 끄고, 텍스처 필터는 `NEAREST`, 게임은 `pixelArt: true`, `antialias: false`, `roundPixels: true`로 설정합니다.
CSS에도 `image-rendering: pixelated`를 적용합니다. 화면 표시 크기를 바꾸어도 게임 내부 해상도는 640×480입니다.

외부 로드 에셋이 없어 `preload()`는 필요하지 않습니다.
`GameScene.create()`는 맵·플레이어·키·콜라이더를 한 번 준비하고, `update()`는 매 프레임 입력을 읽어 속도만 설정합니다.
React state로 프레임마다 플레이어 위치를 관리하지 않습니다.

### 5. 맵과 충돌

`map.ts`의 20×15 숫자 배열로 실제 Phaser Tilemap을 생성하고, 타일 크기는 32px입니다.
외곽의 벽 타일 인덱스 3에 충돌을 설정합니다.
가구는 그림과 정적 Arcade Body가 같은 배치 사각형을 사용합니다.
책상·의자 묶음은 하나의 64×56 직사각형 충돌체이므로 그 묶음의 빈틈은 통과할 수 없습니다.

플레이어는 16×16 그대로 표시되며, 투명 테두리를 고려한 12×14 몸체를 사용합니다.
벽 Tilemap Layer와 가구 Static Group에 각각 collider를 연결하고 월드 경계 충돌도 켭니다.
생성 위치는 `(320, 416)`입니다.

`movement.ts`는 반대 방향 입력을 상쇄한 후 벡터 길이를 1로 정규화하고 속도 100을 곱합니다.
따라서 W+D도 W만 누를 때와 같은 초당 100px입니다.
Arcade의 속도 단위가 px/s이므로 `update()`에서 delta를 다시 곱하지 않습니다.

## 검증 결과와 남은 확인

2026-11-06 기준:

- npm 의존성 설치 성공.
- `npm test`: **4개 파일, 12개 테스트 통과**.
- `npm run build`: 소스와 테스트의 strict TypeScript 검사 및 Vite 빌드 성공.
- Safari에서 시작 → 에디터 전환, 팔레트 선택, 픽셀 색상 변경을 확인.
- 실제 브라우저의 드래그·이동·충돌·재입장·콘솔 점검은 사용자가 직접 확인하기로 하여 최종 수동 검증 대기.

자동 테스트 범위:

| 대상 | 확인 내용 |
| --- | --- |
| 캐릭터 데이터 | 256칸, 8색, 초기 배열 독립성, 잘못된 크기·값·희소 배열 거부 |
| 페인팅 함수 | 정방향·역방향·대각선 보간, 마스크 보호, 원본 불변성 |
| 에디터 DOM 이벤트 | 팔레트 → 연속 포인터 입력 → 완성 전달, 해제·캡처 손실, 초기화, 키보드 활성화 |
| 이동 계산 | 16가지 WASD 조합의 정지/속도 정규화 |
| 맵 데이터 | 외곽 벽, 가구 경계, 안전한 생성 위치 |
| React/Phaser 수명 | StrictMode 생성 예약 취소, 일반 리렌더 시 인스턴스 유지, 포커스 해제 입력 초기화, unmount 시 해제 |

에디터 테스트는 jsdom에서 입력 이벤트를 재현합니다. 수명 테스트는 Phaser를 mock합니다.
따라서 자동 테스트 통과만으로 실제 브라우저 렌더링, GPU 텍스처 색상, OS 키 입력, Arcade 충돌까지 검증했다고 보지는 않습니다.

수동 점검 순서:

- [ ] 팔레트에서 벽돌색을 선택하고 머리와 몸을 가로·대각선으로 드래그하면 중간 칸도 칠해진다.
- [ ] 실루엣 밖에서 누르거나 드래그해도 바깥은 바뀌지 않는다. 밖에서 버튼을 놓은 후 돌아오면 더 칠해지지 않는다.
- [ ] 초기화하면 기본 그림으로 돌아가고, 완성하면 같은 색상·투명 실루엣의 캐릭터가 강의실 아래 중앙에 나타난다.
- [ ] WASD 네 방향과 대각선 이동이 가능하고 키를 놓으면 멈춘다.
- [ ] 아래 중앙에서 W를 길게 눌러 가운데 책상·의자에 막히고, 열린 통로를 통해 다른 가구·외곽 벽에 접근해도 통과하지 않는다.
- [ ] 다시 칠하기 → 수정 → 입장을 여러 번 반복해도 맵/캔버스가 중복되지 않는다.
- [ ] 이동 중 다른 창으로 갔다가 돌아오면 키가 눌린 상태로 남지 않는다.
- [ ] 브라우저 개발자 도구 Console에 치명적인 오류가 없다.

알려진 제한:

- Phaser가 포함된 게임 청크는 약 1.20MB(압축 전)로 Vite의 500kB 경고가 있습니다. 빌드 오류는 아니며, 시작 화면과 분리해 게임 입장 시 로드합니다.
- 완성 데이터의 영구 저장, 실제 멀티플레이 게임 규칙은 없습니다.
- 실제 브라우저의 최종 수동 검증이 끝나기 전까지 전체 완료 조건의 검증 완료로 표시하지 않습니다.

## Phase 2 연결 고려사항

아래는 다음 단계의 설계 참고이며 이번 단계에서 네트워크 코드는 추가하지 않았습니다.

1. `PixelCharacter`는 JSON으로 직렬화 가능한 DTO입니다. FastAPI에서도 16×16, 길이 256, 0~7 정수를 검증하고 마스크·팔레트 버전을 클라이언트와 맞춥니다.
2. `MovementInput`은 엔진과 독립적입니다. 이후 WebSocket에는 위치를 무조건 신뢰해서 보내기보다 입력·순번을 보내고 서버가 이동과 충돌을 검증하도록 연결할 수 있습니다.
3. 네트워크 연결·재접속·메시지 파싱은 별도 모듈로 두고, Scene에는 검증된 캐릭터와 상태를 전달합니다. React의 화면 상태에 매 프레임 월드 전체를 넣지 않습니다.
4. 타일·가구 충돌 데이터와 플레이어 몸체 규격을 서버에서도 동일하게 사용해야 합니다. 현재 Arcade 결과와 서버 이동 계산 간 차이도 테스트해야 합니다.
5. 메시지 타입/버전, 접속과 퇴장, 입력 전송 주기, 서버 상태 전송 주기, 보간/예측, 방별 상태 및 권한을 다음 단계에서 결정합니다. 아직 구현되지 않은 방 관리자 등을 미리 만들지는 않았습니다.

참고한 공식 문서: [Vite 시작 가이드](https://vite.dev/guide/), [Phaser Arcade Physics](https://docs.phaser.io/phaser/concepts/physics/arcade).
